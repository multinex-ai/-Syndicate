# Compact MemQ context

Optimize for correct decisions with less retrieved text, not fewer checks or a claimed token-saving percentage. Skip recall for self-contained tasks. This skill supplements the installed memq-operations skill; use its connection contract when establishing or repairing access, without loading its entire reference library on every query.

## Bind before recall

Resolve the explicit project, checkout and repository ownership. Follow the global account-routing rules: non-Galileo work uses memq_multinex with OAuth as maintainer@example.com; Galileo-owned work requires its verified Umbrage connection. Never attach a fixed Multinex dependency to a Galileo task. Before protected access verify the service-returned principal, effective namespace and intended realm. A configured URL or successful login alone is not that handshake. Missing tools or identity means no private read/write; continue independent work and report the limit. Never extract credentials or bypass the host to obtain missing tools.

## Retrieve only what changes the next action

- State the unresolved question first. Prefer a known task/checkpoint ID over broad semantic search.
- Start with one compact lookup: request at most three relevant summaries, IDs, dates and source references where supported. Target about 1,200 retrieved tokens total as a soft starting budget, not an invented API parameter.
- Expand one source at a time only for a named uncertainty. Stop once the next action is supported, after two expansions add no useful evidence, or after about 3,000 retrieved tokens. Exceed this deliberately when correctness requires it; explain the unresolved issue briefly.
- Reuse already-loaded evidence within the same verified scope. Refresh volatile deployment, account, payment, store and artifact state from the authoritative service before acting or claiming completion. A project/account switch invalidates the previous scope binding.
- Do not retrieve whole transcripts, repeated policy text, unrelated projects, full tool catalogs or duplicate summaries. Use the live tool schema's actual limit/filter fields; trim safely after retrieval if it cannot constrain output. Preserve contradictions and source IDs.

## Keep a small resumable record

At a meaningful phase boundary, when authorized, update one existing task checkpoint rather than appending repeated summaries. Target 300–600 words, preserving: objective; acceptance criteria; project/scope; artifact paths and revisions; verified results with evidence; remaining work; blockers; exact next action; pending or ambiguous external side effects. Retain essential authorization limits even when that exceeds the target. Store references to large artifacts instead of their contents. Never store secrets, raw credentials, unrelated personal data or private reasoning.

Use supported revision/idempotency fields only when present in the schema. Read the returned receipt; reconcile uncertain writes before retry. If MemQ is unavailable, keep an authorized project-local checkpoint marked local-only. Do not imply that it was synchronized.

## Verify efficiency honestly

Judge usefulness by whether the recalled fact changed a correct action or avoided a repeated investigation. Record actual token counts only if the host provides them; otherwise label estimates. Do not claim measured savings from a shorter prompt alone. Do not omit required testing, current-state verification, or source evidence to meet the soft retrieval budget.
