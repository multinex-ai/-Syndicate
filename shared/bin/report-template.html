Flat technical view and account boundaries

Host MCP → SQLite job supervisor → coordinator → role tools or media subprocess → output and validation receipt. Text and media processes share an exclusive lock. The Python ML runtime is the established project implementation; it has ordinary OS-user permissions. Local path checks and the MemQ adapter are not whole-process isolation.

The local agent has its own OAuth enrollment. Each private operation verifies its authenticated subject and namespace before and after dispatch. TF/Galileo ownership blocks Multinex memory access. No credential files or private binding records belong in the portable package. Native generators do not independently execute skill instructions.

On-demand execution and recovery

A simple media request loads the language model once to plan, then the generator. A dependent task may reload the coordinator to use the result. Failed or ambiguous operations remain visible instead of being called successful.

Cancellation, unavailable models, and uncertain writes

Cancel targets only owned worker processes and their descendants. Time and dispatch budgets are finite. Missing files fail admission. A failed OAuth refresh blocks memory while independent work can proceed. A write timeout is an uncertain result: check the existing receipt before retrying; automatic exactly-once execution is not claimed.
